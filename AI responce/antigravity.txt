1. Is this feasible live, open-ended under these constraints?

Verdict: Partly feasible, but ONLY within a tightly bounded narrative domain. Leaning NO if you take "any story a teacher tells" literally.

Where it is YES: It is feasible as a "2D Dynamic Puppet / Stick Theater" constrained to 1–3 humanoid actors interacting with a finite, pre-tagged dictionary of 200–500 props and basic atomic verbs (walk, sit, hold, fall, look, talk, hit).
Where it is an absolute NO: An engine that dynamically visualizes arbitrary teacher speech ("journey of a water drop", "Napoleon's army crossing the Alps", "blood cell fighting a virus", "day and night in a cold shed") without pre-baked templates cannot be done procedurally in real time.
The Core Reason: Video diffusion models (like Sora/Runway) solve open-ended visuals because pixels don't need semantic sockets. Procedural code does. A deterministic layout engine cannot draw "Napoleon's army crossing the Alps" unless code explicitly knows what an "army" looks like (a cluster of 10 miniature sprites), how "crossing" works on a mountain, and how "winter" changes the color palette. Without generative pixels or pre-engineered rules per concept, the system defaults to placing flat icons side-by-side.
2. Which part is the real hard problem, and how to solve it?

Your intuition is correct, but the problem is even deeper than "relations and attach points." The fatal challenges are:

A. The "Socket" Problem (Affordances)
To draw Newton sitting under a tree, the tree asset must possess a semantic socket: under_canopy: {x: 0.4, y: 0.75}.
If you scrape or retrieve a raw SVG from an open library (game-icons, Iconify, Noun Project), you only have a bounding box ([x, y, w, h]).
If you position Newton at tree.y + tree.height, he sits on the grass next to the trunk. If you position him at tree.y + tree.height * 0.5, he overlaps the foliage.
Solution: You cannot use raw on-the-fly SVG retrieval for complex spatial relations. You must use a curated asset registry where every prop has pre-authored Semantic Sockets and a Real-World Metric Scale:
json
{
  "id": "apple_tree",
  "scale_height_m": 4.5,
  "sockets": {
    "under": { "x": 0.35, "y": 0.72 },
    "canopy_top": { "x": 0.5, "y": 0.1 },
    "fruit_spawn": [{ "x": 0.3, "y": 0.35 }, { "x": 0.65, "y": 0.4 }]
  }
}
B. The State Accumulator Problem (Temporal Continuity)

Teachers speak in sequential beats:

"Newton sat under a tree."
"An apple fell on his head."
"He picked it up."

If each line generates an isolated scene graph, the engine will clear the screen or re-layout the tree, causing jarring pops.

Solution: The LLM must not emit a full scene from scratch; it must emit a Scene Delta (Add, Modify, Remove, Trigger Action) against an ongoing working memory state.
C. Visual Polysemy and Scale Disparity
"Apple" (0.1m) vs "Tree" (5m) vs "Alps" (4000m) vs "Water drop" (0.002m).
In vector libraries, all icons are normalized to viewBox="0 0 100 100".
Without an explicit scale attribute, your layout engine will draw an apple the same size as Newton's chest.

To meet the ≤ 2–3s deadline on a 4 GB machine where Whisper already runs:

[ Teacher Speaks ]

Detailed Stack Specs & Licensing

LLM Parser: Groq Cloud API (llama-3.1-8b-instant)

Why 8B over 70B: 8B runs in ~250–400ms on Groq. 70B takes 800–1400ms. In a 2–3s budget where Whisper takes 1s, you cannot afford a 1.5s LLM round-trip.
License: Meta Llama 3.1 Community License (permissive for under 700M monthly active users).
Format: Strict JSON output via Groq's tool-calling or response_format: { type: "json_object" }.

Character & Motion Engine: Analytical 2D Procedural IK (Custom in JS)

Do NOT use neural text-to-motion (MDM, MoMask, T2M-GPT):
Latency: MDM takes 10–30s on CPU.
VRAM: Will crash alongside Whisper on a 4 GB GPU.
License: AMASS and HumanML3D are strictly non-commercial research licenses.
What to use instead: A lightweight procedural stick/puppet rig in PixiJS:
Standardized 14-joint 2D stick skeleton.
Procedural 2-bone analytical Inverse Kinematics (FABRIK or law of cosines) for arms and legs.
8 pre-baked parametric animation clips: idle, walk_cycle, sit_down, fall, point, reach_hold, talk_gesturing, shock_reaction.
License: MIT.

Physics & Tweening: Matter.js + GSAP

Matter.js: Used purely for falling objects, collisions, or ragdoll collapses.
GSAP (GreenSock): Standard for UI / scene graph interpolations, camera panning, and socket transitions.
License: Matter.js is MIT; GSAP is free for standard commercial use (standard license).

Asset Library: Curated Hybrid Line-Art Registry

Base style: 2–3px black stroke vector line art (matching stick figures).
Datasets to extract from: Lucide Icons (ISC License), OpenMoji (CC BY-SA 4.0), or a curated subset of game-icons.net (CC BY 3.0).
Famous Heads: Curated SVG hair/glasses/beard overlays attached to the generic circle head (Newton wig, Einstein hair, Napoleon bicorne hat, Marie Curie hair bun).
Latency Budget (End-to-End)
Local Whisper STT: ~800 ms
Network + Groq Llama 3.1 8B inference: ~350 ms
Client JSON parse, socket resolution & tween dispatch: ~20 ms
Total latency to animation start: ~1.2 – 1.4 seconds. (Comfortably within the 2–3s limit).
4. What Quality to Expect Honestly (vs. YouTube Stick Videos)

You must set user expectations clearly: It will NOT look like a hand-drawn YouTube animation (OverSimplified, Alan Becker, or Casually Explained).

What YouTube hand-animation has: Custom anticipation poses, secondary motion, squash-and-stretch, comedic timing, expressive facial micro-reactions, hand-crafted camera angles.
What this procedural engine will look like: It will look like a high-end procedural digital flannelgraph or a live Scribblenauts stage.
Characters will slide/step into position with mechanical cleanliness.
Poses will resolve via IK (hands snapping cleanly to objects).
Props will pop in with a fade/scale tween.
Speech bubbles will anchor above speaker heads with typewriter text.
If presented as an "animated movie", the user will call it stiff. If presented as a "live visual dynamic blackboard", it will feel like magic.
5. Sentence-by-Sentence Stress Test

Here is how each sentence will perform in this architecture:

1. "Newton was sitting under an apple tree."
Verdict: PASS (Flawless)
Why: Atomic, canonical case.
Execution: Prop apple_tree spawns. Character newton (stick body + curly wig overlay) IK targets the apple_tree.sockets.under coordinate. Pose shifts to sit. Camera centers on the tree.
2. "An apple fell on his head."
Verdict: PASS (Flawless)
Why: Physical event linked to existing actors.
Execution: Prop apple spawns at apple_tree.sockets.fruit_spawn[0]. Matter.js activates gravity. Apple collides with newton.joints.head. Collision trigger fires newton.playClip("shock_reaction") and spawns an impact star/line SVG.
3. "Napoleon's army crossed the Alps in winter."
Verdict: COMPLETE FAILURE (Without specialized domain rules)
Why:
"Army" is an aggregate entity, not a stick figure. A stick figure labeled "Napoleon's army" looks comical.
"The Alps" is a vast geographic terrain, not a localized stage prop.
"Winter" is a global weather state (palette desaturation, falling snow particles).
"Crossed" is a prolonged transit action, not an atomic pose.
Degraded Fallback: The engine spawns a tiny mountain icon, drops a single stick figure with a bicorne hat beside it, and pans the figure across the mountain. It will look like Attempt 2.
4. "Marie Curie worked day and night in a cold shed."
Verdict: FAIL (Semantically Abstract)
Why:
"Worked" has no visual primitive. Does she hold a beaker? Write in a book? Stir pitchblende? The LLM must hallucinate a concrete action ("holding a glowing test tube at a wooden table").
"Day and night" is a temporal span, not a spatial relation. It requires the background sky to tween from yellow to dark blue with a moon.
"In a shed": In a 2D stage, placing an entity "in" an exterior building icon covers the character. You need an "interior cutaway" view.
5. "The drop of water rises into the clouds."
Verdict: PARTIAL (Passable as a diagram, not a character story)
Why:
Non-human actor. If the system assumes all actors are humanoid stick rigs, it breaks.
If the engine treats water_drop as a dynamic rigid body, it simply tweens an SVG drop along the Y axis toward a cloud prop. It works as an animated physics diagram, but character IK is unused.
6. "The boy rode his horse to the village."
Verdict: PARTIAL / FRAGILE
Why:
"Riding" is a compound multi-body constraint. The horse must have a saddle socket and its own walk/gallop cycle. The boy's pelvis must lock to the saddle, legs must switch to a straddle pose, and hands must IK-lock to the horse's neck/reins.
If the horse is just a static SVG icon, the boy sits frozen on a stiff sliding horse graphic (Attempt 2 all over again).
7. "Einstein said to his friend, time is relative."
Verdict: PASS (Flawless)
Why:
Two humanoid rigs (einstein with frizzy hair overlay, friend generic).
einstein faces friend.
Trigger talk_gesturing animation clip on Einstein's arms.
Spawn speech bubble anchored to einstein.joints.head reading "Time is relative."
6. The 48-Hour Proof-of-Concept (Kill-or-Go Test)

Do not build the speech pipeline or LLM integrations yet. Build the deterministic layout and IK renderer first. If this looks stiff or broken, stop.

Day 1: The 2D Procedural Puppet & Socket Engine
Spin up an empty Vite + PixiJS + GSAP page.
Implement a single procedural stick figure drawn with Pixi Graphics:
1 circle (head) + 5 line segments (torso, upper arm, forearm, upper leg, lower leg).
Write a 20-line 2-bone analytical IK function that takes a target (x, y) and places the hand or foot there.

Feed the engine two hardcoded JSON packets with a 2-second delay:

Evaluation Gate:

Look at the screen. Does the stick figure sit naturally under the canopy? Does the apple fall, hit the head, bounce, and make Newton's head bob back?

7. Existing Open-Source Projects to Reuse

Do not build this from zero. Inspect and reuse these tools:

Procedural Stick Figures & 2D Skeletons:

Matter.js Ragdoll Example
: Open-source rigid-body stick figure with constraints. Good reference for physical reaction and falling.
Pose Animator
 (TensorFlow/Open source): Takes 2D vector illustrations (SVG) and drives them using skeletal rigs. (Designed for webcam mocap, but the underlying 2D SVG rigging pipeline is completely open source and runs in the browser).

Semantic Scene Graph Extraction Ideas:

WordsEye
 (Classic NLP research system): Translates English sentences into 3D scenes via a dependency parser and a large database of spatial affordances. Read their papers on "spatial taggers" to see every edge-case trap in advance.
SceneGraphParser
: Stanford's open-source dependency-tree to scene-graph extractor. Can serve as prompt design inspiration for Groq.

Icon Registries with Consistent Line Weights:

Lucide Icons
: 100% consistent 2px stroke, MIT license. Perfect for stick-figure props (books, apples, swords, beakers, carts).
OpenMoji
: Open-source emoji library available in black-and-white line-art format (openmoji-black). High coverage of animals, historical items, and nature.
Final Architectural Recommendation

If you proceed, strictly redefine the feature with the user:

Drop the claim of "any story" (science journeys of water drops, grand battles, weather metaphors).
Explicitly brand the feature as "Stick Storyteller": an interactive digital stick-puppet theater for historical biographies and human dialogues.
Restrict LLM extraction to an Explicit Verb & Relation Vocabulary (e.g., SIT, STAND, WALK_TO, HOLD, DROP_ON, SAY, EMOTE). If an open sentence cannot be mapped to this vocabulary, the LLM falls back to an actor simply standing on stage and speaking the line in a speech bubble.
